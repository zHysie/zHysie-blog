# 组件规范

组件库按照三个层级组织。本文档是 `src/registry.json` 机器可读注册表对应的人工阅读版本。**新增或修改任何界面前都必须先阅读本文档**，优先复用现有基础组件，不能重复创造相同结构。可复用的组合方式记录在 `组合模式.md`。

## 架构

```
基础组件（src/components/ui/**） → 页面区块 → 页面（src/pages/**）
```

- **基础组件：** 第一层通用展示组件，不包含业务逻辑。通过统一出口导入：`import { Button, Card, Badge } from "@/components/ui"`。
- **页面区块：** 第二层页面模块，由基础组件和内容组合而成。通过统一出口导入：`import { Hero, FAQ } from "@/components/sections"`。
- **页面：** 第三层路由，用于排列页面区块并连接内容集合。
- **功能组件：** 与某类内容绑定的模块，例如 `blog/`。它们位于基础组件和页面区块之间，由基础组件组合而成，但只服务一种内容类型。

**新增内容时：** 通用、可复用的界面放入 `ui/**`，并从统一出口导出。页面级模块放入 `sections/`，并从 `sections/index.ts` 导出。与内容集合绑定的界面保留在对应功能目录中，例如 `blog/`。禁止复制已有基础组件，应扩展或组合现有实现。

## 使用规则

- **只能使用设计变量。** 组件中不能写原始 hex、rgb 或 Tailwind 色板工具类，参见 `色彩规范.md`。所有颜色、间距和圆角都来自设计变量。
- **先复用，再新增。** 优先组合 `Card`、`Button`、`Icon`、`Section`、`Grid`，不能重新实现相同组件。新的共享界面放入 `ui/**` 并加入统一出口。
- **通过 `cn` 合并类名。** 每个基础组件都接收 `class` 并正确合并。
- **尽量减少客户端岛。** 目前只有 `FeatureTabs` 是 React 岛；除非交互确实需要客户端框架，否则优先使用 `.astro`。
- **装饰图层**，例如纹理、光晕和网格，必须设置 `aria-hidden` 与 `pointer-events: none`。
- 新增或重命名组件、修改组件属性时，必须同步更新 `src/registry.json`。
